# Parhelion · ZENITH 日冕天台 0.2.0

第二张 Arena 地图。60 × 48 米露天天台，1 单位 = 1 米，Y 轴向上，支持 1v1／1v2／2v2。数据格式与 `arena/`（ASTER 研究站）完全相同，`arena-game/` 直接读取本目录的 `runtime/map.json` 和 `assets/zenith_visual.glb`。ASTER 原地图没有任何改动。

![俯视](previews/01-overview.jpg)

## 设计（0.2：三层阶梯竞技场）

0.1 版和 ASTER 一样是「平地 + 一条高台」，打起来太像，0.2 整张重做成**三层**，并保持**点对称**（(x, z) → (−x, −z)），双方地形完全等价：

| 层 | 高度 | 内容 |
|---|---|---|
| L2 高地 | 4 m | 两端出生台（前有屏风，南北各一条坡道下到角落）；北侧 A 塔、南侧 B 塔，各伸出一个悬台俯瞰中池 |
| L1 台地 | 2 m | 一圈台地围住中池，加上出生台两侧的角落；花坛、树篱、木箱做掩体 |
| L0 日晷池 | 0 m | 28 × 20 米下沉中池，蓝色池底，中央 6 米日晷柱；四条坡道爬出中池 |

打法：出生在高处，开局一路往下打；中池是最短的穿越路线，但上面两层都能往下打。高塔两侧都有坡道，占塔的人能被台地上的人从两边反推。日晷柱挡住两塔之间、两出生台之间的长视线。

## 文件

- `source/make_map.py`：游戏布局（碰撞盒、坡道、锚点、路线），写出 `runtime/map.json`。
- `source/build_glb.py`：纯 Python 3 生成美术模型，不需要 Blender 或任何依赖，输出可重复。
  - `assets/zenith_visual.glb`：每个地图物体一个 `VIS_*` 节点 + 装饰批次，约 1.5 万三角形，1.1 MB，纯因子 PBR 材质，无贴图。台阶侧面陶土色、顶面浅沙色、池底天蓝，三层一眼能分清。游戏加载时统一换成卡通（cel）材质，和 ASTER 风格一致。
  - `assets/zenith_collision.glb`：碰撞代理，仅供查看；游戏碰撞只读 `map.json`。
- `validation/check_glb.py`：检查每个物体都有模型、碰撞代理与 `map.json` 完全一致、可见模型不超出碰撞盒、无贴图、预算。
- `previews/`：在游戏里截的图。

装饰（窗框、花坛上的叶团、塔顶遮阳帆和旗、日晷光环、远处的塔和云海）全部没有碰撞，叶团最多高出花坛 0.2 米；子弹可以穿过这部分装饰。

## 重建

```sh
python3 source/make_map.py
python3 source/build_glb.py
python3 validation/check_glb.py
cd ../../arena-game && npx vitest run test/maps.test.ts
```

`arena-game/test/maps.test.ts` 用游戏本身的物理、视线和寻路代码检查每张注册地图：锚点落地且不在实体内、敌对出生点互不可见、`routes` 里四条路线正反两向都能用真实移动走通、寻路网格连通所有出生点/掩体/目标点、四个 Bot 能打出击杀；ZENITH 另外检查点对称、两座塔看不到敌方出生点、中池看不到任何出生点、两塔中心互相不可见、确实有三层可走（中池占比不到 40%）。

## 已知限制

- 新地图的竞技平衡只经过 Bot 对局和静态视线检查，还没有真人对局验证。
- 各层边缘没有护栏碰撞，可以直接跳下（下落不掉血）。
- 预览图是浏览器面板里的截图，不是 Blender 渲染。

# 本能寺建筑衔接与复制发射器修复

本能寺本堂、僧舍与弯曲屋顶之间补入按真实屋顶三角面求交的连续封板；四座角楼补齐上层立柱、梁圈与屋顶连接，东门补齐门楣和屋架，钟楼补齐梁圈与钟体吊架。本堂外廊梁连接原有立柱和墙体。

复制发射器的守卫胜利不再依赖当前交互操作。正常开枪、近战、闪避中断操作后，真实战斗胜利仍会写入对应的 `adventure_guard_N_cleared` 存档标志。再次操作、会话重置与读档都不会重新刷出已清除的守卫；三处装置分别记录。未完成的战斗仍可重试，关闭发射器仍需正常交互三秒。

## 地图发布范围

源码生成器与正式 `world_kyoto.glb`、运行时 `world_kyoto.visual.glb` 一并更新，流式清单尺寸已刷新。`world_kyoto.core.glb` 和布局 JSON 保留原始文件。逐网格解码对比确认只有 `Honnoji` 变化，其余模型的属性、三角形、材质、碰撞三角形顺序以及所有节点均保持一致。

`world/tools/repair-honnoji.ts` 可将当前生成器的本能寺视觉批次写入指定的既有 GLB；它直接复制新增压缩缓冲区，避免对其余模型二次编码。调用时可传入基准文件与输出文件；完整地图与 visual 文件分别处理后，需更新流式清单并构建网站。

## 验证

- `honnoji-continuity.test.ts` 对完整地图和实际 visual 文件检查本堂、僧舍、四座角楼、东门与钟楼的连接。
- 京都任务、路线、导出预算、材质与流式交付检查：48 项通过。
- 发射器与主线检查：13 项通过；真实主程序输入检查包含“近战中断操作 → 击败守卫 → 保存 → 再操作而不刷新守卫 → 关闭发射器”。该检查采用非 GPU 渲染器，并通过真实战斗伤害接口完成清敌。
- Arena 644 项、网站 13 项通过；整站构建与类型检查通过。

既有存档可直接使用；此前未记录的守卫胜利无法从旧存档推断，更新后首次清除会开始持久保存。
